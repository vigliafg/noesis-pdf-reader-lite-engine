# Noesis PDF Reader Lite — Engine (CLI)

Headless command-line edition of the **Noesis PDF Reader Lite** engine: it
extracts PDF pages to Markdown with the same adaptive layout engine as the
desktop app, and exposes the **same export options** as its batch-export
wizard — page selection, content (original / translated / both), translation
engine and languages, translate-missing, image embeds, and the merged / zip /
per-page-folder formats.

No GUI, no PyQt: just the engine, the translator and the exporter.

## Install

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

or install it as a console command:

```bash
pip install .
noesis-pdf-engine --version
```

OCR (scanned pages) uses Tesseract through PyMuPDF. Install the `tesseract`
binary with the language data you need, or point `--tessdata` /
`TESSDATA_PREFIX` at a tessdata directory.

## Usage

```bash
# extract pages 1–10 to a single Markdown file
noesis-pdf-engine book.pdf --pages 1-10 --content original -o book.md

# extract + translate to English, original and translation side by side
noesis-pdf-engine book.pdf --pages 3,5,10-12 --content both --dst en

# one file per page, into a folder
noesis-pdf-engine book.pdf --format folder --out out/ --name capitolo

# a zip of one Markdown file per page
noesis-pdf-engine book.pdf --pages all --content original --format zip -o pages.zip

# scanned PDF with Italian + English OCR
noesis-pdf-engine scan.pdf --content original --ocr-lang eng+ita
```

The input PDF is the only positional argument. With no options it extracts
**all** pages, keeps images, and writes a single `<name>.md` in the current
directory.

## Options

| Option | Default | Meaning |
|---|---|---|
| `--pages SPEC` | `all` | `all`, `7`, `100-103`, `1,3,5-7` (1-based) |
| `--content` | `translated` | `original` · `translated` · `both` |
| `--engine` | `google` | `google` · `microsoft` |
| `--src` / `--dst` | `auto` / `it` | source / target language |
| `--translate-missing` / `--no-translate-missing` | on | translate pages with no cached translation |
| `--images` / `--no-images` | on | keep Markdown image embeds |
| `--format` | `merged` | `merged` · `zip` · `folder` |
| `-o`, `--out PATH` | cwd | output file (merged/zip) or folder (folder) |
| `--name NAME` | PDF name | base name of the output |
| `--ocr-lang LANG` | from `--src` | Tesseract language(s), e.g. `eng+ita` |
| `--tessdata DIR` | — | `TESSDATA_PREFIX` for OCR |
| `--pipeline` | `ir` | `ir` (default) · `current` (legacy) |
| `--json` | off | machine-readable summary on stdout |
| `-q` / `-v` | — | quiet / verbose |
| `--version` | — | print the version |

These mirror the desktop wizard 1:1 (the wizard's "current page" default
becomes `all` for a non-interactive tool).

## Output formats

* **merged** — one file, each page as a `<!-- pagina N -->` block, pages
  separated by `---`.
* **zip** — a zip with one `{name}_pag{NNNN}.md` per page.
* **folder** — one `{name}_pag{NNNN}.md` per page in a folder.

Bodies have the extraction header stripped, exactly like the desktop export.
With `--no-images`, Markdown image embeds are removed.

## Notes on translation

`--content translated` (and `both`) uses the same public Google/Microsoft
endpoints as the desktop app, so it needs network access. The CLI has no
on-disk translation cache: pages are always translated on the fly, and
`--no-translate-missing` therefore makes translated pages fail (there is no
cache to fall back to) — it exists only for parity with the desktop option.

## Relationship to the desktop repo

The engine modules (`ir_layout.py`, `layout_engine.py`, `page_model.py`,
`layout_proxies.py`, `pages.py`, `i18n.py`, `theme.py`) are copied **verbatim**
from the desktop repository, and `main.py` is the Qt-free core of the desktop
`main.py` regenerated by a script. The desktop repo is the source of truth:

```bash
python tools/sync_from_desktop.py                 # sibling checkout
python tools/sync_from_desktop.py --desktop /path/to/noesis-pdf-reader-lite
```

`tests/test_sync_parity.py` asserts the copies and the generated `main.py`
match the desktop checkout byte-for-byte when it is present (and skips in CI).

## Tests

```bash
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

The suite runs the CLI end-to-end on synthetic PDFs, unit-tests the export
composition, and includes the engine tests ported from the desktop repo
(corpus-dependent cases skip themselves when the corpus is absent).
